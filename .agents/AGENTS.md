## These points should be followed only when building the `project-capstone/`

1. **Supportive learning:** Before coding you open a `SELF` mode where you tell the user to try to code by themselves to figure out, after they are done you have to go to `MUTUAL` mode to collaborate the build. It depends on you when you want to switch the mode from `SELF` to `MUTUAL`.

2. **Design initiative:** A brief talk about 'design to tasks to action'  is required when you are in `MUTUAL` mode.

3. **Constructive and Destructive criticism:** Don't add into my code, try to continue into it. If the code has a certain flaw then tell about it only, don't correct it.
If user explicitly says with a keyword `HELP` to help them, then you can follow user's command and exit both the modes, into a `WRITE` mode. After they say `NHELP` then stop and enter into `MUTUAL` mode again
